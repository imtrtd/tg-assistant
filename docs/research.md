# Публичный поиск

Команды ищут только **открытые** каналы и группы Telegram. Запрос выполняет не сам бот
(Bot API так не умеет), а отдельная пользовательская сессия Telethon. Бот присылает
результат в чат.

Не реализовано и не будет добавлено: поиск по телефону, история ников, оценка даты
регистрации человека, запросы к слитым базам и любое раскрытие личности по закрытым
данным. Личный аккаунт в `/channel` не принимается. Инвайт-ссылки (`t.me/+…`,
`joinchat`) и внутренние `t.me/c/…` тоже.

`/find` по-прежнему ищет **заметки**. Поиск каналов в этом репозитории — `/sources`
(в отдельном боте-прототипе команда называлась `/find`).

## Команды

| Команда | Что делает |
|---|---|
| `/search <слова>` | Посты в публичных каналах. Даты: `from:YYYY-MM-DD`, `to:YYYY-MM-DD` (синонимы `since:`, `until:`, `till:`), `last:24h`, `last:7d`, `last:2w`. Канал: `in:@username` или `in:https://t.me/username`. |
| `/sources <тема>` | Публичные каналы и чаты по теме. |
| `/channel @username` | Сводка: название, описание, подписчики, частота постов, средние просмотры, топ источников пересылок, связанные и упомянутые каналы. |
| `/watch <термин>` | Следить за упоминанием (бренд, ник, ссылка) в публичных каналах. |
| `/unwatch <термин>` | Снять наблюдение. |
| `/watches` | Список наблюдений в этом чате. |

Примеры:

```
/search imtrtd last:30d
/search оболочка from:2026-01-01 to:2026-03-31 in:@publicchannel
/sources osint tools
/channel @durov
/watch example.com
```

Первый проход `/watch` запоминает уже существующие совпадения и **не** рассылает их.
Сообщение приходит только по новым публичным постам. Проверка идёт в том же процессе,
что и напоминания: на общем Postgres её выполняет только лидер (см. [failover.md](failover.md)).

Числовой id человека из пересылки не показывается. Если у источника нет публичного
имени, в топ пересылок он не попадает.

## Секреты

Их задаёте вы. В репозитории их нет.

| Переменная | Обязательна | Что это |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` или `BOT_TOKEN` | да | Токен от @BotFather |
| `ALLOWED_USER_IDS` | да | Telegram id через запятую. Пустой список никого не пускает |
| `API_ID` | для поиска | Число с https://my.telegram.org |
| `API_HASH` | для поиска | Строка с той же страницы |
| `TELEGRAM_SESSION` или `SESSION_STRING` | для поиска | Строка StringSession, не файл `.session` |
| `DATABASE_URL` | нет | По умолчанию SQLite `sqlite+aiosqlite:///data/bot.db`. Для Postgres: `postgresql+asyncpg://…` |

Пока `API_ID`, `API_HASH` или `TELEGRAM_SESSION` пустые, команды поиска отвечают, что
функция выключена. Заметки и напоминания при этом работают.

### Строка сессии

На своём компьютере, один раз:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e .
export API_ID=12345678
export API_HASH=put-api-hash-here
python -m tg_assistant.research.login
```

Скрипт спросит телефон, код из Telegram и пароль 2FA, если он включён, и напечатает
строку. Её целиком вставляют в `TELEGRAM_SESSION`. Файл `.session` не создаётся.
Строка — ключ от аккаунта: не коммитьте её и не присылайте в чат.

Для постоянного поиска лучше отдельный аккаунт, не основной: частые запросы ловят FloodWait.

`api_id` и `api_hash`: войдите на https://my.telegram.org → API development tools →
создайте приложение и скопируйте поля. Это не токен бота.

## Лимиты

Команды поиска ограничены по пользователю (`RESEARCH_RATE_LIMIT_COMMANDS` за
`RESEARCH_RATE_LIMIT_WINDOW_SECONDS`, по умолчанию 8 за 60 секунд). FloodWait короче
порога Telethon пережидает сам. Более длинный — до `RESEARCH_FLOOD_MAX_WAIT_SECONDS`
(120) и не больше `RESEARCH_FLOOD_RETRIES` (5) повторов. Дальше команда просит
попробовать позже.

Наблюдения и ключи уже виденных постов `(watch_id, peer_id, message_id)` лежат в той
же базе, что и заметки. На эфемерном диске задайте `DATABASE_URL` на Postgres
(например бесплатный Neon) — тогда список наблюдений не пропадает вместе с контейнером.
Без `DATABASE_URL` используется SQLite в `data/`.
