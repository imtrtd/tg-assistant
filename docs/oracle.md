# Бесплатный всегда включённый хостинг: Oracle Cloud

Публичный поиск и `/watch` должны работать постоянно: хост, который засыпает без
входящего HTTP, пропускает упоминания. На ноябрь 2026 года практичный бесплатный
вариант — **виртуальная машина Always Free в Oracle Cloud**, форма
`VM.Standard.E2.1.Micro` (AMD, 1 ГБ ОЗУ).

Почему она, а не соседние бесплатные тарифы:

| Вариант | Почему не он |
|---|---|
| Oracle Always Free, `VM.Standard.E2.1.Micro` | Не засыпает, диск сохраняется, 10 ТБ исходящего трафика в месяц, уже есть Docker-деплой этого репозитория. Бессрочно, пока действует Always Free. |
| Oracle Ampere A1 | Тоже Always Free и мощнее, но в 2026 году в популярных регионах часто «Out of host capacity». Берите A1, только если микро-ВМ не создаётся, а A1 — создаётся. |
| Render Free | Веб-сервис засыпает через 15 минут без входящего трафика. Диск при остановке стирается. Отдельный cron — платный. Бот на polling входящего HTTP не получает, поэтому будет спать. |
| Koyeb Free | Единственный бесплатный инстанс засыпает через час без входящего трафика. Это нельзя отключить. Тома и воркеры на бесплатном тарифе недоступны. |
| Hugging Face Spaces (бесплатный CPU) | Засыпает без запросов. Для фоновой проверки упоминаний не подходит. |
| Google Cloud `e2-micro` | Тоже бессрочно бесплатен **одна** ВМ в `us-west1`, `us-central1` или `us-east1`, диск 30 ГБ. Исходящий трафик сверх 1 ГБ/мес уже платный, а ВМ не в этих регионах тарифицируется сразу. Легко получить счёт. Имеет смысл только если Oracle не выдаёт мощность, и только в одном из трёх регионов США. |

Карта для проверки личности нужна и Oracle, и Google. Сам Always Free после пробных
кредитов остаётся бесплатным, если не выходить за лимиты.

Ограничение Oracle: простаивающую Always Free ВМ могут забрать, если 7 дней подряд
загрузка CPU ниже 20%, сеть ниже 20% и (для A1) память ниже 20%. Бот с polling и
проверкой упоминаний раз в несколько минут обычно этому не соответствует, но если
машину всё же удалят, строка `TELEGRAM_SESSION` и при желании Postgres в `DATABASE_URL`
позволяют поднять её заново без нового входа в Telegram.

Сессия Telethon в файл не пишется: процесс читает `TELEGRAM_SESSION`. Наблюдения по
умолчанию лежат в SQLite на диске ВМ (`data/bot.db`). Если диск эфемерный, задайте
`DATABASE_URL`.

## Что подготовить заранее

Секреты вводятся только у вас. В git их нет.

1. Токен бота у [@BotFather](https://t.me/BotFather): `/newbot`. Это `TELEGRAM_BOT_TOKEN` (синоним `BOT_TOKEN`).
2. Ваш числовой Telegram id — в `ALLOWED_USER_IDS`. Пока список пуст, бот отвечает «доступ закрыт» и показывает id.
3. `API_ID` и `API_HASH` на https://my.telegram.org → API development tools.
4. Строка сессии `TELEGRAM_SESSION` — шаг 4 ниже, на своём компьютере.
5. Необязательно: `DATABASE_URL`, если не хотите SQLite на диске ВМ.

## 1. Аккаунт и виртуальная машина

1. Откройте https://www.oracle.com/cloud/free/ и создайте аккаунт Always Free.
2. В консоли OCI: **Compute → Instances → Create instance**.
3. Образ: **Ubuntu 24.04**.
4. Форма: **VM.Standard.E2.1.Micro**, метка Always Free. Не переключайте на платную форму.
5. Регион — домашний регион тенанта. Если микро-форма недоступна, смените домен доступности (availability domain) и повторите. A1 берите только когда микро-ВМ создать нельзя.
6. Загрузочный том оставьте по умолчанию (около 47 ГБ). В бесплатный объём 200 ГБ это помещается.
7. Сеть: публичный IPv4. Входящий порт **22** с вашего IP. Порты 80 и 443 боту для polling не нужны. Откройте их, только если поднимаете мини-приложение через Caddy ([deploy.md](deploy.md)).
8. Добавьте свой SSH-ключ и сохраните приватный ключ у себя.
9. Создайте инстанс и дождитесь состояния Running. Скопируйте публичный IP.

Необязательно: в поле cloud-init можно вставить файл `deploy/oracle/cloud-init.yaml` из
репозитория. Он ставит Docker. Репозиторий и секреты он не клонирует.

## 2. Поставить бота на ВМ

С локальной машины (пользователь образа Ubuntu — `ubuntu`):

```bash
ssh -i /путь/к/ключу ubuntu@ПУБЛИЧНЫЙ_IP
```

На сервере, от root:

```bash
curl -fsSL https://raw.githubusercontent.com/imtrtd/tg-assistant/main/deploy/setup-vps.sh | sudo bash
```

Скрипт ставит Docker, при нехватке памяти — файл подкачки 1 ГБ, клонирует репозиторий
в `/opt/tg-assistant` и копирует `.env.example` в `.env`, если его ещё нет.

### Обновление

Сервер обновляется сам: таймер `tg-assistant-update` раз в 10 минут проверяет ветку
`main` и, если там новые коммиты, запускает `deploy/update.sh` (копия базы, git pull,
пересборка, перезапуск). После мержа бот обновится в течение ~10 минут, плюс время сборки.

- Журнал: `journalctl -u tg-assistant-update -n 50`
- Когда следующая проверка: `systemctl list-timers tg-assistant-update`
- Обновить сейчас: `sudo /opt/tg-assistant/deploy/update.sh`
- Выключить: `sudo systemctl disable --now tg-assistant-update.timer`
  (или поставить заново с `AUTO_UPDATE=0`)

Таймер ставит `setup-vps.sh`. На сервере, который настраивали раньше, его ставит
та же команда, что и при первой установке, — она же обновит бота:

```bash
curl -fsSL https://raw.githubusercontent.com/imtrtd/tg-assistant/main/deploy/setup-vps.sh | sudo bash
```

**Деплой по кнопке с телефона.** GitHub → репозиторий → Actions → **Deploy** →
Run workflow. Нужны секреты репозитория (Settings → Secrets and variables → Actions):
`ORACLE_HOST` — IP сервера, `ORACLE_SSH_KEY` — приватный ключ целиком,
`ORACLE_USER` — если пользователь не `ubuntu`. Без секретов кнопка ничего не делает.

## 3. Секреты на сервере

```bash
sudo nano /opt/tg-assistant/.env
```

Минимум:

```
TELEGRAM_BOT_TOKEN=123456789:токен-от-BotFather
ALLOWED_USER_IDS=111111111
API_ID=12345678
API_HASH=хеш-с-my.telegram.org
TELEGRAM_SESSION=строка-из-шага-4
```

`BOT_TOKEN` вместо `TELEGRAM_BOT_TOKEN` тоже принимается. `SESSION_STRING` — синоним
`TELEGRAM_SESSION`.

База, если оставляете SQLite, уже прописана:

```
DATABASE_URL=sqlite+aiosqlite:///data/bot.db
```

Файл появится в `/opt/tg-assistant/data` (том Docker). Каталог `data/` и файлы `*.session`
в git не попадают.

### Необязательный Postgres (Neon)

Нужен, если диск машины негде хранить или вы хотите базу отдельно от ВМ.
Бесплатный план Neon (на ноябрь 2026): без карты, 1 ГБ на проект, 100 CU-часов
вычислений в месяц, compute засыпает через 5 минут простоя. Бот, который постоянно
ходит в эту базу, может исчерпать 100 часов за месяц. Для всегда включённой ВМ
проще оставить SQLite на её диске. Neon — запасной вариант для эфемерного диска.

1. Создайте проект на https://neon.tech и скопируйте строку подключения.
2. Замените схему `postgresql://` на `postgresql+asyncpg://` и добавьте SSL, если его нет:

```
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST/DB?ssl=require
```

Пароль в строке не коммитьте. Миграции применятся при старте бота, таблицы
`research_watches` и `research_seen_posts` создадутся вместе с остальной схемой.

## 4. Строка сессии — только у себя на компьютере

Не вводите телефон и код на чужой ВМ, если ей не доверяете. На своём компьютере,
в клоне репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
export API_ID=12345678
export API_HASH=хеш-с-my.telegram.org
python -m tg_assistant.research.login
```

Введите телефон аккаунта для поиска, код из Telegram и пароль 2FA, если включён.
Скрипт напечатает одну длинную строку. Вставьте её в `TELEGRAM_SESSION` на сервере.
В чат и в git её не кладите.

Поиск лучше вести с отдельного аккаунта: лимиты Telegram (FloodWait) относятся к нему.

## 5. Запуск

На сервере:

```bash
cd /opt/tg-assistant
sudo docker compose up -d --build
sudo docker compose logs -f
```

В логе должно появиться `Bot @... started` и строка про авторизованную пользовательскую
сессию. Если секретов поиска нет, бот всё равно стартует, а `/search` ответит, что
поиск выключен.

Один токен — один процесс. Остановите бота на своём компьютере, иначе Telegram
будет чередовать обновления (ошибка 409).

Напишите боту `/start` с аккаунта из `ALLOWED_USER_IDS`, затем `/search` или `/watch`.
Команды и фильтры — в [research.md](research.md).

## 6. Мини-приложение

Отдельный домен не нужен. `WEB_APP_URL` оставьте пустым: контейнер сам поднимает
бесплатный туннель Cloudflare, и кнопка «Открыть» в Telegram начинает работать.
Адрес (`https://….trycloudflare.com`) виден в логе строкой `Mini App is available at`
и меняется после перезапуска — бот обновляет кнопку сам. Подробности и постоянный
домен — в [mini-app.md](mini-app.md). Поиску мини-приложение не нужно.

## Если ВМ не создаётся

- «Out of host capacity» — другой availability domain, другая попытка позже, либо
  форма A1 на 1 OCPU и 6 ГБ, если лимит тенанта это позволяет.
- Не выбирайте форму без метки Always Free: она списывает пробные кредиты, а потом деньги.
- Google `e2-micro` — запасной путь и только в `us-west1`, `us-central1` или `us-east1`.
  Дальше те же шаги: Ubuntu, Docker, `deploy/setup-vps.sh`, те же переменные в `.env`.
