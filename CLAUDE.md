# tg-assistant

Telegram-бот на Python 3.11+ и aiogram 3.

- Код: `src/tg_assistant/`. Новые команды — отдельный модуль в `handlers/` с функцией `create_router()` (не роутер на уровне модуля), подключается в `handlers/__init__.py:build_router`; команду добавить в `BOT_COMMANDS`.
- В хендлерах доступны `session` (AsyncSession) и `user` (db.User) — их кладёт `DbMiddleware`.
- Время в БД, по которому что-то срабатывает, — колонки `UTCDateTime` (aware UTC); в хендлерах переводить в `ZoneInfo(user.timezone)`.
- Схема БД меняется только через миграции: `alembic revision --autogenerate -m "..."`. При запуске бота миграции применяются автоматически.
- Настройки — только через `config.Settings` (pydantic-settings, `.env`). Секреты не коммитить.
- Перед коммитом: `ruff format . && ruff check . && pytest`.
- PR: после зелёного CI сразу мержить (squash), без ожидания ревью.
- Деплой: Docker (`Dockerfile`, `docker-compose.yml`), скрипты в `deploy/`, инструкция в `docs/deploy.md`; Railway — `railway.json`, `docs/railway.md` (порт из `PORT`, адрес из `RAILWAY_PUBLIC_DOMAIN`). В `Dockerfile` нет `VOLUME` — Railway его не принимает. Контейнер работает от uid 1000, база — в томе `data/`.
- Хостинг: компьютера у владельца часто нет, бот должен жить в облаке, и предпочтительно бесплатно. Бесплатный основной вариант — Oracle Cloud Always Free (`docs/oracle.md`, `deploy/setup-vps.sh`). Railway (`docs/railway.md`) — платный около 5 $/мес. Cloudflare бесплатно бота не запустит: нужен постоянный процесс, а Containers только на Workers Paid. Render Free засыпает: резервный узел будит `.github/workflows/keepalive.yml`. Из облачной сессии Claude не достучаться до api.telegram.org, api.cloudflare.com и регистраций у хостеров: проверку в Telegram и регистрацию делает владелец, токены — только в `.env` или в secrets хостинга, никогда не в чат.
- ПК + облако на одной базе Postgres (`leader.py`, `docs/failover.md`): включается сам при Postgres в `DATABASE_URL`; работает только лидер (`pg_try_advisory_lock`, `NODE_NAME`/`NODE_PRIORITY`). Код, который шлёт сообщения или запускает фоновые задачи, должен работать только на лидере.
- Надёжность (`ops.py`, `backup.py`, `docs/watchdog.md`): сторож пишет `data/heartbeat` и убивает зависший процесс; `HEALTHCHECK_PING_URL` — healthchecks.io; бэкап базы в Telegram раз в `BACKUP_INTERVAL_HOURS`; перенос между базами — `python -m tg_assistant.copy_db`.
- Публичный поиск (`research/`, `handlers/research.py`, `docs/research.md`): `/search`, `/sources`, `/watch` через отдельную сессию Telethon (`TELEGRAM_API_ID`/`TELEGRAM_API_HASH`/`TELEGRAM_SESSION`). Только открытые каналы и чаты; не добавлять поиск по телефону, раскрытие личности и запросы к слитым базам. `/find` — это поиск по заметкам.
- Веб-интерфейс (`web/`): сервер aiohttp в том же процессе, включается настройкой `WEB_APP_URL`. Вход — initData мини-приложения (`Authorization: tma ...`) или cookie: после одноразовой ссылки из `/web` или кнопки Telegram Login Widget (`/auth/telegram`, домен задаётся в @BotFather `/setdomain`; имя бота — `settings.bot_username`). Страница в `web/static/` без сборки; действует CSP: никаких inline-скриптов и стилей, пользовательский текст вставлять только через `textContent`.
- Архив чатов (Telegram Business, `handlers/business.py`, `db/archive.py`): отправитель бизнес-апдейта — собеседник владельца, а не пользователь бота. Middleware такие апдейты пропускают без проверки и без `user` (`middlewares/business.py`); владельца находит `resolve_owner` по `business_connection_id`. В бизнес-чаты никогда ничего не отправлять — только владельцу в личку. Единственное действие в бизнес-чате — удалить собственное сообщение владельца «@бот текст» после сохранения заметки (`handlers/mention.py`).
- Мини-приложение: адрес берётся из `settings.web_app_url` в момент вызова; при `WEB_TUNNEL_METRICS_URL` бот при старте получает адрес туннеля cloudflared (`web/tunnel.py`) и меняет его на лету. Ссылки внутрь приложения — `settings.app_url(open=..., chat=...)`. Архив во фронтенде — `web/static/archive.js` (грузится до `app.js`), API — `web/archive_api.py`; отправка из архива владельцу — `archive_delivery.py`.
- Темы в личке (`topics.py`): при режиме тем бот создаёт постоянные темы. Куда пойдёт сообщение в личку, решает `TopicsRequestMiddleware` по `TOPIC_KIND`: рассылки оборачивать в `with topic_kind(...)`, а `message_thread_id` вручную не подставлять. Новые команды — добавить в `COMMAND_KINDS`.
